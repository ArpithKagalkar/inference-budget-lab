BUILT TO BE SCRUTINIZED

Know what you are measuring.

A useful optimization is one you can reproduce and explain.

01 / OBJECTIVE

Cost under constraints

Minimize token cost per submitted request, subject to minimum exact-match quality and maximum p95 end-to-end latency. Eligibility uses point estimates; a 95% Wilson interval is reported for quality. A passing run is evidence on this sample, not a production guarantee.

02 / DATA & ROUTING

Calibrate, freeze, evaluate

A separate configurable validation split selects among four difficulty thresholds. The router uses text features for negation, historical context, and length. The selected threshold is frozen before all policies see the same test fixtures. Split-specific IDs prevent identical prompts, but templates are shared: this is not an independent real-world benchmark.

03 / SIMULATION

An explicit model of the system

Seeded response errors vary by model tier and fixture difficulty. Latencies are sampled from an illustrative service-time distribution. A shared worker pool models FIFO queueing under Poisson or burst arrivals. Tokens use a character-based estimate. This simulator does not model GPU batching, KV-cache behavior, or real model accuracy.

04 / LIVE ENDPOINTS

Measured calls and explicit costing

Configure two OpenAI-compatible endpoints. API models use provider token prices and usage. Local models use measured response time multiplied by a stated GPU-hour rate. The client measures full response time and its own queueing. Live calibration replays measured service times to estimate candidate latency; final policies are benchmarked with real calls.

05 / ACCOUNTING

No invisible fallback costs

This MVP routes once and does not retry or cascade. Failed calls remain in the denominator and count as quality failures. Calibration spending is recorded separately. Token pricing is suitable for APIs; self-hosted GPU rental and idle capacity require separate infrastructure accounting.

06 / NEXT EXPERIMENT

Move toward production evidence

Replace synthetic fixtures with independently labeled tickets, run repeated trials, randomize policy execution order, and test workload drift. Add measured quantization, batching, and cache experiments against a real serving engine before claiming inference efficiency gains.
